\chapter{The specification and the brute-force reference}\label{chap:spec}

This chapter states the specification of the points that ratpoints finds, the brute-force reference
that lists them, the statements that comparator certifies, and the command-line program
\verb|ratpoints-lean| with its differential tests. The specification is the one part whose
correctness no proof can check, so wherever there is a choice it copies what the C code computes,
and each of its clauses is compared with ratpoints~3.1.1 below (Section~\ref{sec:spec-evidence}
summarizes the evidence). Where the library function \verb|find_points| and the command-line program
differ, as in the order of the checks on the input, the specification and the model follow the
program.

Throughout, $c = [c_0, c_1, \dots, c_n]$ is a list of integers, the coefficient list of the
program's input with the constant term first, so that $n + 1$ is its length; $d$ is its
\emph{degree}, the largest index with $c_d \ne 0$ ($0$ if there is none); and
\[ D = d + (d \bmod 2), \qquad N = 2 \lceil n/2 \rceil = 2 \lfloor (n+1)/2 \rfloor \]
are $d$ and $n$ rounded up to even numbers ($N = 0$ for the empty list). $H$ is a natural number,
the height bound.

\section{The binary form}

\begin{definition}[The binary form]\label{def:binaryForm}
  \lean{Ratpoints.degree, Ratpoints.binaryForm}\leanok
  For integers $x$ and $z$,
  \[ F_c(x, z) = \sum_{i=0}^{d} c_i\, x^i z^{D-i}. \]
\end{definition}

\begin{remark}[What the C code computes]\label{rem:degree}
  This is the form the C code evaluates. The library drops the leading zero coefficients
  (\csource{find_points.c}{4624}{4632}), so it works with the degree $d$, and its exact check
  computes $\sum_{k \le d} c_k a^k b^{d-k}$ by Horner's rule in the numerator $a$, with the
  products $c_k b^{d-k}$ computed once per denominator $b$, and multiplies by $b$ once more when
  $d$ is odd (\csource{find_points.c}{5291}{5298}); the result is $F_c(a, b)$. For instance
  \verb|'-2 0 0 1' 130 -q| prints $(129 : 3830 : 100)$, and $3830^2 = 100 \cdot (129^3 - 2 \cdot
  100^3) = F_c(129, 100)$. The library refuses every input with
  $\lceil d/2 \rceil < \lceil n/2 \rceil$, so on an accepted input $D = N$; this held in every
  accepted run of the empirical checks, with and without \verb|-s| and \verb|-k|.
\end{remark}

The model evaluates the form in the manner of the C code, in the brute-force reference
(Section~\ref{sec:bruteForce}) and, from stage~C1 on, in the exact check of the sieve, and each of
these evaluations is proved equal to $F_c$.

\begin{definition}[The binary form of degree $N$]\label{def:binaryFormPoly}
  \uses{def:binaryForm}
  \lean{Ratpoints.binaryFormPoly, Ratpoints.eval_binaryFormPoly}\leanok
  \[ \Phi_c = \sum_{i=0}^{n} c_i X^i Z^{N-i} \in \QQ[X, Z], \]
  the polynomial made homogeneous of degree $N$, which is the form the refusals speak about (the
  C code's ``polynomial not squarefree as a binary form of even degree''). When
  $\lceil d/2 \rceil = \lceil n/2 \rceil$, that is on every input the library accepts and whenever
  $\Phi_c$ is squarefree, $D = N$ and $\Phi_c(x, z) = F_c(x, z)$ for all integers $x$ and $z$.
\end{definition}

The refusal theorem uses Mathlib's \verb|Squarefree|: no square of a non-unit divides $\Phi_c$. The
units of $\QQ[X, Z]$ are the nonzero constants, so this is squarefreeness over $\QQ$ (over $\ZZ$,
$4(X^2 + Z^2)$ would not be squarefree, while the program accepts \verb|4 0 4|), and $0$ is not
squarefree. In the Lean definitions the coefficients are written \verb|c.getD i 0|, since Mathlib's
notation \verb|c[...]| for cycles makes \verb|c[i]| fail for a list named \verb|c| wherever all of
Mathlib is imported.

$\Phi_c$ is also Mathlib's homogenization \verb|Polynomial.homogenize f N| of
$f = \sum c_i X^i \in \QQ[X]$ (Lemma~\ref{lem:squarefree_binaryFormPoly}). Mathlib says nothing yet
about the squarefreeness of a homogenization, and stage~D proves (Lemma~\ref{lem:homogenize}): for a
polynomial $p$ over a domain and $m \ge \deg p$, the homogenization of $p$ of degree $m$ is
squarefree if and only if $p$ is squarefree and $m \le \deg p + 1$; together with the facts this
needs that Mathlib lacks: a factor of a nonzero homogeneous polynomial over a domain is homogeneous,
\verb|Squarefree| is preserved by multiplicative equivalences, and the reversal of $f$ swaps $X$ and
$Z$ in its homogenization. These are candidates for Mathlib, in \verb|Ratpoints/Mathlib|. With them,
``$\Phi_c$ squarefree'' is ``$N \le d + 1$ and $f$ squarefree'', the two conditions the C code
tests.

\section{The points}

\begin{definition}[Normalized point of height at most $H$]\label{def:IsPoint}
  \uses{def:binaryForm}
  \lean{Ratpoints.IsPoint}\leanok
  A triple $(x, y, z)$ of integers is a
  \emph{normalized point of height at most $H$} on $y^2 = F_c(x, z)$ if
  \[ y^2 = F_c(x, z), \quad \gcd(x, z) = 1, \quad z > 0 \text{ or } (z = 0 \text{ and } x = 1),
     \quad |x| \le H, \quad z \le H. \]
\end{definition}

Its clauses, compared with the program:
\begin{itemize}
  \item \emph{The normalization} is the one the program prints. Since $D$ is even,
    $F_c(-x, -z) = F_c(x, z)$, and in the weighted projective plane with weights $(1, D/2, 1)$,
    where the points of the curve live, $(-x : (-1)^{D/2} y : -z)$ is the same point as
    $(x : y : z)$. As both signs of $y$ are listed, the condition can pick $z > 0$, and $x = 1$
    when $z = 0$ (where $\gcd(x, 0) = |x|$ forces $x = \pm 1$).
  \item \emph{The points at infinity} are therefore the triples $(1, y, 0)$ with
    $y^2 = F_c(1, 0) = c_D$: for odd $d$, $c_D = c_{d+1} = 0$ and there is the one point
    $(1 : 0 : 0)$; for even $d$, $c_D = c_d$, which gives $(1 : \pm\sqrt{c_d} : 0)$ when $c_d$ is a
    square, and nothing otherwise. These are exactly the points at infinity of the C code
    (\csource{find_points.c}{5068}{5105}).
  \item \emph{Both signs of $y$}: a point with $y \ne 0$ gives the two triples $(x, \pm y, z)$,
    as the program prints both.
  \item \emph{The box is closed}: $|x| = H$ and $z = H$ are included, as in the C code (the
    numerators run over $-H, \dots, H$ and the denominators over $1, \dots, H$).
  \item \emph{Coprimality} is \verb|Int.gcd|, with $\gcd(0, z) = z$, so $x = 0$ occurs only as
    $(0, y, 1)$, as in the C code's test (\csource{sift.c}{318}{343}).
  \item \emph{The height bound applies to the points at infinity too} ($|1| \le H$), so for
    $H = 0$ there are no points at all. The program refuses $H = 0$, so this never shows; it
    keeps the predicate uniform.
\end{itemize}

\begin{definition}[The set of points]\label{def:points}
  \uses{def:IsPoint}
  \lean{Ratpoints.points, Ratpoints.finite_setOf_isPoint, Ratpoints.mem_points}\leanok
  The finite set of normalized points of height at most $H$ on
  $y^2 = F_c(x, z)$. It is finite because $|x| \le H$, $0 \le z \le H$ and
  $|y| \le y^2 = F_c(x, z) \le \sum_i |c_i| H^D$.
\end{definition}

\verb|IsPoint| is decidable (through a named instance built with \verb|inferInstanceAs|, since
instance search does not unfold a definition), and \verb|degree| and \verb|binaryForm| are
computable, so the specification file can check facts taken from the program's output by
\verb|decide|: for instance that $(129, 3830, 100)$ is a point of $y^2 = x^3 - 2$, that
\verb|1 1 1 1 0| (degree $3$, the one vanishing leading coefficient allowed for even $n$) has the
point $(1, 0, 0)$, and that $(1, 1, 0)$ is not a point of \verb|1 0 0 0 2|, whose leading
coefficient $2$ is not a square.

\section{The refusals}\label{sec:refusals}

The refusal theorem of stage~D (Theorem~\ref{thm:refusals}) has its predicate in the specification:
with the Sturm step on, as in a run of the program without options, and for all sieving parameters,
\verb|findPoints| refuses $(c, H)$ if and only if $c$ has fewer than two or more than
$\mathrm{maxDegree} + 1$ entries (Definition~\ref{def:maxDegree}), $H = 0$ or $H \ge 2^{63}$ (a
height that is not a C \verb|long|), or $\Phi_c$ is not squarefree. In a default run with $2$ to
$\mathrm{maxDegree} + 1$ coefficients and $1 \le H \le 2^{63} - 1$, the program refuses exactly the
inputs for which $\Phi_c$ is not squarefree. The reason: $\Phi_c = Z^{N - d}\, \Phi^0$, where
$\Phi^0$ is the homogenization of $f = \sum c_i x^i$ in degree $d$, which is prime to $Z$; so
$\Phi_c$ is squarefree if and only if $N - d \le 1$ and $f$ is squarefree. The library tests the
first condition when it drops the leading zeros (\csource{find_points.c}{4624}{4632}) and the second
with the remainder sequence of $f$ and $f'$ in the Sturm step, the remainder chain of
Definition~\ref{def:sturmChain} (\csource{sturm.c}{99}{163}); its test of $c_0 = c_1 = 0$ in the
reversal (\csource{find_points.c}{4744}{4749}) catches $X^2 \mid \Phi_c$, which the remainder
sequence would also catch.

\begin{definition}[The bound on the degree]\label{def:maxDegree}
  \lean{Ratpoints.maxDegree}
  \leanok
  $\mathrm{maxDegree} = 100$, the largest degree of a polynomial that ratpoints accepts, the value
  of \verb|RATPOINTS_MAX_DEGREE| (\csource{ratpoints.h}{33}{33}): a list of coefficients has at
  most $\mathrm{maxDegree} + 1 = 101$ entries.
\end{definition}

Like the other constants that the C code fixes when it is compiled, the bound is a definition of the
model with the value of the default build, in \verb|Ratpoints/Model/Constants.lean|, and no proof
depends on its value. The model keeps the bound, which 3.1.1 imposes in the library
(\csource{find_points.c}{4557}{4558}) as well as in the program. In the order of the checks the
library and the program differ, and the model follows the program: the library checks the leading
zeros before the height, so that \verb|5 0| with $H = 0$ is \verb|NON_SQUAREFREE| for it, while the
program checks the coefficient list and the height before it calls the library
(\csource{main.c}{362}{380}) and reports error~4; a height of $2^{63}$ or more, which the library
cannot be given, its height being a C \verb|long| (\csource{ratpoints.h}{362}{362}), the program
refuses with the same error when it reads it. So \verb|findPoints| refuses more than
$\mathrm{maxDegree} + 1$ coefficients and fewer than two, then $H = 0$ and $H \ge 2^{63}$, with the
program's error numbers 3, 5 and~4, and after these, with error~8, the forms that the set-up of the
library refuses as not squarefree (Definition~\ref{def:findPoints}).

With the options of stage~D the predicate changes: under \verb|-s| (no Sturm step) the program
refuses, besides the coefficient count, $H = 0$ and $H \ge 2^{63}$, exactly the inputs with
$N - d \ge 2$ and, when the reversal check runs (no \verb|-k|, no search intervals, the full range
of denominators), those with even $d$ and $c_0 = c_1 = 0$; under \verb|-s -k| only those with
$N - d \ge 2$. This is the predicate of the refusal theorem with the Sturm step off
(Theorem~\ref{thm:refusals}).

\section{The brute-force reference}\label{sec:bruteForce}

\begin{definition}[Brute-force search]\label{def:bruteForce}
  \uses{def:binaryForm}
  \lean{Ratpoints.bruteForce, Ratpoints.BruteForce.pointsOfDen, Ratpoints.BruteForce.pointsAbove, Ratpoints.BruteForce.numerators, Ratpoints.BruteForce.scaledCoeffs, Ratpoints.BruteForce.horner, Ratpoints.BruteForce.degree, Ratpoints.BruteForce.degree_eq}
  \leanok
  The list, computed in the model, of the triples found by testing, in this order, the candidate
  $(1, 0)$ if $H \ge 1$, and then the pairs $(x, z)$ with $1 \le z \le H$, $-H \le x \le H$ and
  $\gcd(x, z) = 1$, with $z$ ascending and, for each $z$, $x$ ascending. For each candidate, $v =
  F_c(x, z)$ is computed; if $v \ge 0$ and $v = y^2$ for $y = \lfloor \sqrt{v} \rfloor$, the triple
  $(x, y, z)$ is output, followed by $(x, -y, z)$ if $y \ne 0$.
\end{definition}

This is the core of \verb|verify-test4.py| of the C repository (which compares point sets only), in
the model (Lean core, no Mathlib). It evaluates $F_c$ as the C code's exact check does (Horner's
rule in $x$ on the products $c_k z^{d-k}$, computed once per $z$, and one more factor $z$ when $d$
is odd), so that the candidate $(1, 0)$ needs no case of its own, and it takes the square root with
\verb|Nat.sqrt|; the degree $d$ is computed by the expression of \verb|degree|
(Definition~\ref{def:binaryForm}), which the model cannot import. It takes no hypothesis on $c$ or
$H$, and it models no C code, so it cites none. Written as nested \verb|List.flatMap|s rather than
loops, its membership proof is direct. Compiled, it tests one to two million coprime pairs per
second (Lean's \verb|Int| is a GMP number beyond $\pm 2^{31}$, which $F_c$ exceeds at small heights
already), so whole test suites fit at heights up to about $1000$; there are about $1.2\, H^2$
coprime pairs per curve. Its order is the program's for the inputs that the program neither reverses
nor searches in divisor order: on the \verb|test4.sh| runs of height at most $1000$ that print
points with \verb|-q|, the \verb|ratpoints-lean| of stage~B, which printed the reference, reproduced
the output of the C program byte for byte, except for reversed polynomials and for odd degree with
$|c_d| \ne 1$, where the two agreed as sets. Since stage~D the output of \verb|findPoints| is mapped
back after a reversal, and since stage~E it is that of the reference of the polynomial searched over
the denominators in the order of its search (Theorem~\ref{thm:findPoints_order}), which is the order
of the program on every point list of the differential tests, all compared in their order; the order
is spelled out in terms of the polynomial in Theorem~\ref{thm:order}, with the divisors of the
leading coefficient in the order of binary counting over its primes, and the protocol of the
callback of the library in Theorem~\ref{thm:protocol}; stage~G also adds the options of the output,
and stage~H the search region of the options (Definition~\ref{def:regionSpec}): the order and the
membership hold for the points in the search region, the reference filtered by it.

\begin{theorem}[The brute-force reference finds exactly the points]\label{thm:bruteForce}
  \uses{def:bruteForce, def:IsPoint, def:points}
  \lean{Ratpoints.mem_bruteForce_iff, Ratpoints.nodup_bruteForce, Ratpoints.toFinset_bruteForce}
  \leanok
  For every list $c$ and every $H$: a triple lies in
  $\mathrm{bruteForce}(c, H)$ if and only if it is a normalized point of height at most $H$;
  the list has no duplicates; and its set of elements is $\mathrm{points}(c, H)$.
\end{theorem}

\begin{proof}
  \leanok
  The candidate $(1, 0)$ gives the points with $z = 0$, since $\gcd(x, 0) = 1$ and the
  normalization force $x = 1$; the pairs give those with $z > 0$. The model's evaluation is
  $F_c$, and $v = (\lfloor \sqrt{v} \rfloor)^2$ holds exactly when $v \ge 0$ is a square. The
  candidates are distinct, and $y \ne -y$ for $y \ne 0$, so there are no duplicates. The third
  statement follows from the first two.
\end{proof}

\section{What comparator certifies}\label{sec:comparator-ab}

\verb|comparator/Challenge.lean| imports Mathlib and the model. It restates \verb|degree|,
\verb|binaryForm| and \verb|IsPoint| verbatim and states, with \verb|sorry|, the first two
statements of Theorem~\ref{thm:bruteForce} (\verb|challenge_mem_bruteForce_iff| and
\verb|challenge_nodup_bruteForce|); \verb|comparator/Solution.lean| proves them by
\verb|Ratpoints.mem_bruteForce_iff| and \verb|Ratpoints.nodup_bruteForce|. \verb|binaryFormPoly| is
restated too, for the refusal theorems of stage~D, and \verb|points| stays out of the challenge:
comparator compares the full declarations that a certified statement reaches, the proofs of theorems
included, so the finiteness proof inside \verb|points| would have to be reproduced term for term;
and these two theorems say everything the \verb|Finset| statement says. (A computable \verb|points|,
filtering an explicit box with the bound $\max |F_c|$ for $|y|$, would avoid the proof term, but it
is not needed.) The specification can be restated because it is elaborated with Mathlib, as the
challenge is; a definition of the model, elaborated without Mathlib, has other instance terms and is
always imported, never restated. Since stage~C1 the challenge also states membership and no
duplicates for \verb|findPoints| for well-formed parameters, since stage~D for every option,
membership since stage~G for $\mathrm{noCheck}$ false, with $y \ge 0$ under $\mathrm{noY}$, and
\verb|wf_sieveParams|, and since stage~D the refusal theorems with the Sturm step on and off
(Theorem~\ref{thm:refusals}), which since stage~F2 also refuse the heights of $2^{63}$ or more, over
\verb|findPoints|, \verb|Options|, \verb|Params|, \verb|Params.WF|, \verb|SieveOptions|,
\verb|sieveParams| and \verb|maxDegree|, imported from the model (Section~\ref{sec:sieveTheorems}),
and since stage~G the protocol of the delivery (Theorem~\ref{thm:protocol}), over
\verb|findPointsWith|, \verb|Outcome|, \verb|Answer|, \verb|Delivery| and \verb|Delivery.deliver|,
the three statements under $\mathrm{noCheck}$ (Theorem~\ref{thm:noCheck}), and the order theorem
(Theorem~\ref{thm:order}), over the definitions of \verb|Ratpoints/Spec/Order.lean| with their
instance and the decidability instance of \verb|IsPoint|, restated verbatim, and \verb|maxDivisors|,
imported from the model; since stage~H membership, the order and the statements under
$\mathrm{noCheck}$ on the elements hold for the points in the search region, and the refusal
theorems add the search intervals that are not well formed and refuse $c_0 = c_1 = 0$ without the
Sturm step only for the whole box (Section~\ref{sec:certifiedH}), over the definitions of
\verb|Ratpoints/Spec/Region.lean| with their decidability instances, restated verbatim, and the
doubles $\mathrm{Double}$ of the search intervals of the options, imported from the model; for
\verb|Squarefree| the challenge and the specification import
\verb|Mathlib.Algebra.Squarefree.Basic|, for the prime factors the challenge and the file of the
order \verb|Mathlib.Data.Nat.Factors|, and for the values of the doubles the challenge and the file
of the region \verb|Mathlib.Order.WithBotTop| and \verb|Mathlib.Algebra.Order.Field.Rat|, so that
the challenge still imports exactly the Mathlib modules among the public imports of the files of the
specification that it restates. So the challenge has twelve statements
(Section~\ref{sec:certifiedG}), which \verb|lake comparator --paranoid| accepted on 2026-10-17, with
Lean's kernel and the five external checkers bundled with Lean; Section~\ref{sec:sieveTheorems}
records the earlier acceptances.

\section{The command-line program}\label{sec:cli}

The Lean program is a program of its own, the executable \verb|ratpoints-lean|, with the command
line of ratpoints. Eventually it offers the full functionality of ratpoints except the threads and
the other hardware-dependent features. It prints the points of the sieve of
Chapters~\ref{chap:sieve} and~\ref{chap:words} with the set-up of Chapter~\ref{chap:setup} (in
stage~B those of the brute-force reference, in stage~C1 those of the plain sieve), so that the test
scripts of the C repository can run it as \verb|RP=ratpoints-lean|:
\begin{itemize}
  \item it prints what ratpoints prints: the points, through the callback \verb|process| of
    \verb|main.c|, by default one line \verb|(x : y : z)| per point, and without \verb|-q| the
    report around them (Definition~\ref{def:cliReport}), the banner, the curve, the height bound and
    the search region of the command line (message~3) before the points and what the search did and
    the count of the points found after them, but for the messages on the search intervals that the
    search gives back (message~8, stage~H) and on the moduli used (message~4, stage~I); under
    \verb|-v|, which \verb|-q| cancels in \verb|main.c|, the report of \verb|-v|, without the report
    of the library that ratpoints prints then;
  \item it reads the first two arguments as \verb|main.c| does: the coefficient list as one argument
    and the height, with its checks, messages and exit codes, in its order: fewer than two arguments
    (2, with the banner and the usage), a malformed coefficient (11), more than $\mathrm{maxDegree}
    + 1$ coefficients (3), fewer than two (5), a height outside $1, \dots, 2^{63} - 1$ (4)
    (\csource{main.c}{362}{380}, \csource{main.c}{700}{740}, \csource{main.c}{1036}{1056}); every
    message goes to standard output as a blank line, the message and a blank line;
  \item it reads the tuning options \verb|-n -N -P -p -F -j -J -r -R -U -A -C -Q -W -t| with the
    validation of \verb|main.c| (error~6 and the usage for a missing or malformed argument of the
    thirteen that take one, \csource{main.c}{437}{532}; \verb|-j| and \verb|-J| take none):
    \verb|-n -N -P -p -F -j -J| go into the sieving parameters (Definition~\ref{def:sieveParams}),
    and the others, which tune only the heuristics of the C program and its threads, are ignored
    (until stage~I, but for \verb|-t| for good; in 373 runs of the C program they did not change the
    \verb|-q| output);
  \item it reads \verb|-k| and \verb|-K|, which forbid and allow the reversal of the polynomial,
    and \verb|-s| and \verb|-S|, which switch the Sturm step off and on, \verb|-S| with the depth
    that the next word gives when there is one and it does not start with \verb|-|, the last of
    each pair winning, into the options of \verb|findPoints| (Definition~\ref{def:Options};
    \csource{main.c}{594}{601}, \csource{main.c}{638}{649}), with error~6 for a malformed depth;
  \item it reads the options of the output as \verb|main.c| reads them, \verb|-x -X -y -Y| into
    the options of \verb|findPoints| and \verb|-z -Z -1 -i -I| and the formats and strings of
    \verb|-f -fs -fm -fe| into the settings of the output (Section~\ref{sec:outputCli});
  \item it reads the search region as \verb|main.c| reads it, the intervals of \verb|-l| and
    \verb|-u| with their exact ends and the doubles outward of them, with error~7 for intervals that
    are malformed, not alternating, too many or not ordered, and the range of the denominators of
    \verb|-dl| and \verb|-du| into the options of \verb|findPoints|, runs the search on the
    intervals joined where their doubles meet, and prints only the points of the search region of
    its command line (Section~\ref{sec:regionCli}, Theorem~\ref{thm:cliRegion}); an unknown option
    fails with error~6, as in \verb|main.c|;
  \item its banner starts with the line \verb|This is ratpoints-lean-0.1|, so that
    \verb|test4.sh| filters it as it does the C program's, and the differential tests exchange
    the banners and the usages of the two programs;
  \item it refuses a binary form that is not squarefree with error~8 as ratpoints does with the
    same options, since \verb|findPoints| refuses what the program refuses
    (Theorem~\ref{thm:refusals}), and it prints the points in the order of ratpoints
    (Theorem~\ref{thm:findPoints_order}).
\end{itemize}
The numbers need a reader of their own that mirrors \verb|scan_mpz| and \verb|scan_long|
(\csource{main.c}{700}{740}): \verb|main.c| accepts a leading \verb|+| and any C white space
around and between the numbers (\verb|test4.sh| has a tab-separated list and a height ending in
a carriage return), which core's \verb|String.toInt?| does not; and core's \verb|String.toNat?|
accepts the digit separator \verb|_|, which \verb|main.c| refuses. The program lives in the model
library, in \verb|Ratpoints/Model/Cli.lean|, its readers of the numbers in
\verb|Ratpoints/Model/CliNumbers.lean|, with a \verb|Main.lean| that imports only the model, as the
\verb|lean_exe| target \verb|ratpoints-lean|. Its parts, with the lines of \verb|main.c| that they
mirror:

\begin{definition}[Reading numbers]\label{def:cliNumbers}
  \lean{Ratpoints.Cli.intOfWord?, Ratpoints.Cli.onlyWord?, Ratpoints.Cli.longOfString?}
  \leanok
  The readers of the numbers of the command line, in \verb|Ratpoints/Model/CliNumbers.lean|, on the
  words of an argument, its maximal runs of characters other than C white space (the space and the
  characters from tab to carriage return): an integer of the coefficient list as \verb|scan_mpz|
  reads it, an optional sign \verb|+| or \verb|-| and at least one decimal digit, of any size
  (\csource{main.c}{700}{717}); the one word of an argument with only white space around it, which
  \verb|strtol| and \verb|strtod| skip before a number and \verb|only_space_after| checks after it
  (\csource{main.c}{724}{728}); and a C \verb|long| as \verb|scan_long| reads it, an integer from
  $-2^{63}$ to $2^{63} - 1$ (\csource{main.c}{733}{740}). A real number is read as
  \verb|scan_double| reads it, with the double that \verb|strtod| gives in the C locale
  (Definition~\ref{def:cliEnds}).
\end{definition}

\begin{definition}[The failures]\label{def:cliFailure}
  \uses{def:reversal, def:searchIntervals}
  \lean{Ratpoints.Cli.Failure, Ratpoints.Cli.Failure.message, Ratpoints.Cli.Failure.status, Ratpoints.Cli.Failure.ofRefusal, Ratpoints.Cli.banner, Ratpoints.Cli.usage}
  \leanok
  The ways in which \verb|ratpoints-lean| refuses its command line, with the message and the exit
  status of each. These are the errors of \verb|main.c| that the command line can cause, 2 (fewer
  than two arguments), 3 (more than $\mathrm{maxDegree} + 1$ coefficients), 4 (a height bound that
  is not a C \verb|long| of at least $1$), 5 (fewer than two coefficients), 6 (a malformed option),
  7 (an end of a search interval that is missing or no number, two lower or two upper ends in a row,
  more than $\mathrm{maxDegree}$ intervals, or ends that are not ordered), 8 (a binary form that is
  not squarefree) and 11 (a coefficient that is not an integer), and error~9, which \verb|main.c|
  gives for the codes of the library other than \verb|RATPOINTS_NON_SQUAREFREE| and
  \verb|RATPOINTS_NO_MEMORY| (error~10, which the model cannot return), for the model the refusal
  $\mathrm{badArgs}$ of search intervals that are not well formed
  (Definition~\ref{def:searchIntervals}), which the command line never passes; on each,
  \verb|main.c| prints a blank line, the message and a blank line, and exits with the number of the
  error (\csource{main.c}{1036}{1048}, \csource{main.c}{1050}{1053}, \csource{main.c}{1054}{1056});
  on error~2 it prints the banner (\csource{main.c}{43}{48}) and the usage
  (\csource{main.c}{77}{88}) instead of a message, and on error~6 both. The banner is that of
  \verb|ratpoints-lean| and the usage that of ratpoints, with the name of the program changed. A
  refusal of $\mathrm{findPointsWith}$ (Definition~\ref{def:findPointsWith}), whose refusals are
  those of $\mathrm{findPoints}$ (Definition~\ref{def:reversal}), is the failure with the same
  number, as \verb|main.c| turns the code that the library returns for a form that is not squarefree
  into error~8 and its other codes but \verb|RATPOINTS_NO_MEMORY| into error~9
  (\csource{main.c}{256}{261}); the reading of the command line meets the other refusals first, and
  the command line gives no search intervals that the library refuses, so that only error~8 can come
  from $\mathrm{findPointsWith}$.
\end{definition}

\begin{definition}[The command line]\label{def:cliInput}
  \uses{def:cliNumbers, def:cliEnds, def:cliFailure, def:maxDegree, def:sieveParams, def:Options,
    def:cliOutput, def:cliIntervals}
  \lean{Ratpoints.Cli.coefficients, Ratpoints.Cli.heightBound, Ratpoints.Cli.checkOptions, Ratpoints.Cli.input}
  \leanok
  The coefficient list, the height bound and the values of the options of a command line, those that
  set the sieving parameters, the options of the search and the settings of the output
  (Definition~\ref{def:cliOutput}), or its first failure, in the order of \verb|main.c|: fewer than
  two arguments fail (\csource{main.c}{210}{214}); \verb|read_input| (\csource{main.c}{315}{316},
  \csource{main.c}{691}{692}) reads the first argument into the array of the coefficients
  (\csource{main.c}{54}{54}), constant term first, integers separated by white space, and fails on a
  word that is not an integer, wherever it stands, then on more than $\mathrm{maxDegree} + 1$
  integers, then on fewer than two (\csource{main.c}{318}{318}, \csource{main.c}{362}{375}); the
  second gives the height bound, a C \verb|long| of at least $1$ (\csource{main.c}{378}{379}); and
  the options are read from left to right, each told by the character after its \verb|-| and, for
  \verb|-f| and \verb|-d|, by the one after that (\csource{main.c}{393}{400},
  \csource{main.c}{414}{416}), from the options of the search with the default search region and the
  height bound as the largest denominator (\csource{main.c}{333}{336}, \csource{main.c}{380}{380}).
  The tuning options, of which \verb|-p -F -t -n -N -R -A -P| take a C \verb|long| and
  \verb|-r -U -C -Q -W| a real number, have their arguments checked (\csource{main.c}{437}{532});
  the switches \verb|-q| and \verb|-v| go into the settings of the output, and the values of
  \verb|-p -n -N -P -F| and the switches \verb|-j| and \verb|-J| into the values of the options of
  Definition~\ref{def:sieveParams} (\csource{main.c}{578}{593}), the last one winning, and the other
  tuning options are ignored (until stage~I, but for \verb|-t| for good); \verb|-k| and \verb|-K|
  (\csource{main.c}{594}{601}) and \verb|-s| and \verb|-S| (\csource{main.c}{638}{649}) go into the
  options of Definition~\ref{def:Options}, the last of each pair winning: the reversal forbidden or
  allowed, and the depth of the Sturm step, $-1$ for \verb|-s|, and for \verb|-S| the C \verb|long|
  that the next word gives when there is one and it does not start with \verb|-| (error~6 if it is
  malformed), and else $\mathrm{defaultSturm}$; \verb|-x| and \verb|-X|, \verb|-y| and \verb|-Y| go
  into $\mathrm{noCheck}$ and $\mathrm{noY}$ of the options, and \verb|-z -Z -1 -i -I| into the
  settings of the output (\csource{main.c}{602}{637}), of each pair the last one winning; \verb|-f|,
  \verb|-fs|, \verb|-fm| and \verb|-fe| take the next word, whatever it is, as the format or the
  string, and \verb|-f| followed by a character other than \verb|s|, \verb|m| and \verb|e|, and a
  missing word, are error~6 (\csource{main.c}{533}{577}); \verb|-l| and \verb|-u| read the ends of
  the search intervals (Definition~\ref{def:cliIntervals}), a missing end failing with error~7, and
  \verb|-dl| and \verb|-du| the C \verb|long| that follows them as the least and the largest
  denominator of the options of the search, the last one winning, with error~6 for a missing or
  malformed argument and for a word \verb|-d| followed by another character
  (\csource{main.c}{650}{668}); after the options a pending interval is completed, the search
  intervals of the options are the doubles of the intervals read and the exact ends go into the
  settings of the output (\csource{main.c}{679}{679}), the format is the default unless \verb|-f|
  gave one, and \verb|-q| cancels \verb|-v| (\csource{main.c}{688}{688}); any other word fails with
  error~6.
\end{definition}

\begin{definition}[The program]\label{def:cliRun}
  \uses{def:cliInput, def:cliFailure, def:findPointsWith, def:cliProcess, def:cliReport,
    def:sieveParams, def:Options, def:cliRegionTest}
  \lean{Ratpoints.Cli.run, Ratpoints.Cli.main}
  \leanok
  \verb|ratpoints-lean| reads its command line (\csource{main.c}{195}{198}). On a failure it prints
  the failure's message and exits with its status; otherwise, for the values $s$ of the options that
  set the sieving parameters, the options $o$ of the search (Definition~\ref{def:Options}) and the
  settings $u$ of the output, it prints the head of the report (Definition~\ref{def:cliReport}),
  nothing under \verb|-q|, and runs the search with a callback
  $\mathrm{findPointsWith}(c, H, \mathrm{sieveParams}(s), o')$ with the callback of the program on
  its data (Definition~\ref{def:cliProcess}) where ratpoints calls \verb|find_points|
  (\csource{main.c}{251}{252}), for the options $o'$ of $o$ with the search intervals joined where
  their doubles meet (Definition~\ref{def:cliRegionTest}, \csource{main.c}{248}{248}), the data
  holding the intervals of the command line before the join; on a refusal it prints the message of
  the failure after the head and exits with its status, and otherwise it prints what the callback
  printed, the points of the search region of its command line in the order in which the search
  delivers them, that of the list of $\mathrm{findPoints}$ (Theorem~\ref{thm:protocol}), which is
  that of Theorem~\ref{thm:order}, the callback passing over the points that lie outside the
  intervals of the command line; then the string before the points if it printed no point
  (\csource{main.c}{265}{265}), the string after them (\csource{main.c}{267}{267}) and the end of
  the report, nothing under \verb|-q|; and it exits with status~0 (\csource{main.c}{284}{285}). It
  writes its output once it is computed and, like ratpoints, ignores a failed write, but for one
  case: when the reader of the output is gone, the signal \verb|SIGPIPE| ends ratpoints, and the
  shell reports the status $141 = 128 + 13$; the Lean runtime ignores that signal, so that the write
  of \verb|ratpoints-lean| fails instead, and it exits quietly with status~141. Since ratpoints
  flushes its output after every point (line 187 of \verb|main.c|), a reader that leaves early, like
  \verb|head|, ends it at the next point, while \verb|ratpoints-lean| notices only a reader that is
  gone when it writes: an output that fits into the pipe ends with status~0.
\end{definition}

\section{The differential tests of stage~B}

The script \verb|scripts/difftest.py| compares \verb|ratpoints-lean| with the C program built at the
pin and with its recorded outputs, in six suites in stage~B (stage~C1 adds two,
Section~\ref{sec:sieveCli}, stage~C2 raises the largest height to $30000$ and adds the suite
\verb|test4high|, run locally, Section~\ref{sec:wordsCli}, stage~D compares the refusals, the
options of the search and the order, Section~\ref{sec:setupCli}, stage~E every point list in its
order, Section~\ref{sec:denCli}, stage~G the options of the output, the reports and the suite
\verb|outputs|, Section~\ref{sec:outputTests}, and stage~H the search region, the suite
\verb|regions| and the runs of \verb|test4.sh| and \verb|test3.sh| with a search region,
Section~\ref{sec:regionTests}):
\begin{itemize}
  \item \verb|test4.sh| against \verb|testbase4|, split at the \verb|#| header lines (five of which
    are glued to the end of the preceding output line): 565 of its 582 runs, among them the outputs
    that the script filters through \verb|grep found|, \verb|grep 'Curve equation'| and
    \verb|grep -c .|, compared after the same filter with the banner exchanged; the others are the
    four whose filter looks at the report of the library under \verb|-v| and 13 with heights from
    $40000$ to $100000$, which the suite \verb|test4high| compares (Section~\ref{sec:wordsCli});
  \item \verb|test3.sh| invocation by invocation against the C program, since it has no announce
    lines: 16 of its 21 runs (5 have filtered outputs; one, at a height above the largest height
    of the tests, $30000$, on which the C program prints nothing, is compared since stage~E);
  \item the curves of \verb|testdata.h|, \verb|testdata-many.h| and \verb|testdata-degrees.h|,
    read from the pinned checkout, at a reduced height $h$ ($100$ by default): the C program run
    at height $h$ prints exactly the reference lines of \verb|testbase*| restricted to
    $|a| \le h$ and $b \le h$, in the same order (checked for $h = 10, 100, 1000$), so these 1206
    runs need no run of the C program;
  \item 300 random polynomials of degree 1 to 8 with coefficients from $-10$ to $10$ at heights
    up to 30, against the C program (from stage~C1 on, when \verb|ratpoints-lean| runs the sieve,
    a theorem relates the list of the sieve to that of the brute force, since stage~E
    Theorem~\ref{thm:findPoints_order}, so that the brute force needs no test of its own);
  \item 303 hand-written command lines (\verb|scripts/difftest_cases.py|) for the checks that
    \verb|main.c| makes on the coefficients, the height and the options: white space and signs, the
    bounds of a \verb|long|, the grammar of \verb|strtod|, every option with a missing or malformed
    argument, the options of the search, the options of the output, the formats and the strings of
    \verb|-f -fs -fm -fe|, the report, the refusals of forms that are not squarefree with and
    without \verb|-s| and \verb|-k|, and the order of the checks; the two searches at the height
    $10^{12}$ that both programs stop at a point at infinity, \verb|'1 0 1'| and \verb|'3 2 -1 12'|
    with \verb|-q -1|, run with a timeout of $30$ seconds and a cap of $4$~GB on the memory; besides
    these, the usage of \verb|ratpoints-lean|, and failed writes: a standard output that is a pipe
    without a reader, where \verb|SIGPIPE| must end the C program and \verb|ratpoints-lean| must
    exit with status~141, both without a message (unless nothing is written), and a full device,
    where both must ignore the failure;
  \item 300 random polynomials at small heights with random options of the output, \verb|-q| or
    \verb|-v|, formats and strings, the moduli pinned at times, against the C program (the suite
    \verb|outputs|, since stage~G);
  \item 800 random command lines, eight in each round, with words that the readers of numbers of
    \verb|main.c| accept or refuse in many ways, and options of the output with format words in
    UTF-8, against the C program.
\end{itemize}
Point lists are compared in their order (Section~\ref{sec:denCli}); a report, the output of a run
without \verb|-q|, exactly, with the banner exchanged for that of the C program and the messages 4
and 8 dropped from the report of the C program only, also the refusal of a form that is not
squarefree without \verb|-q|, and the output under \verb|-v| by its lines; the outputs with the
options of the output, under \verb|-x| as Sections~\ref{sec:outputTests} and~\ref{sec:regionTests}
say; messages and exit codes are compared exactly (but for a pipe without a reader, where the two
programs end differently by design), with the banner and the usage of the two programs exchanged;
and \verb|ratpoints-lean| must write nothing to its standard error (it runs with
\verb|LEAN_ABORT_ON_PANIC=1|, so that a panic of the Lean runtime ends it). CI builds the C program
at the pin (\verb|make|, with \verb|libgmp-dev|) and the Lean program, and runs the script.

\section{Files and names}

The declarations live in the namespace \verb|Ratpoints|, but for the lemmas that Lean core lacks
(\verb|Ratpoints/Proof/Containers.lean| and \verb|Ratpoints/Proof/Bits.lean|) and the candidates for
Mathlib (\verb|Ratpoints/Mathlib|), which carry their names in the namespaces of core and of
Mathlib, and for \verb|main| (\verb|Main.lean|) and the statements of \verb|comparator/|, which are
at the root. The module says which part a declaration belongs to, and \verb|scripts/check_layout.py|
keeps the parts' imports apart: the specification is \verb|Ratpoints/Spec/Basic.lean|, with examples
by \verb|decide| taken from the output of the program, \verb|Ratpoints/Spec/Order.lean| the order of
the points in that output (Section~\ref{sec:order}), checked by \verb|decide +kernel| on outputs of
the program too, and \verb|Ratpoints/Spec/Region.lean| the value of a double of the C code from its
bits and the search intervals that ratpoints accepts (Chapter~\ref{chap:region}), with examples by
\verb|decide +kernel|; the constants of the C code are in \verb|Ratpoints/Model/Constants.lean|; the
brute-force reference is \verb|Ratpoints/Model/BruteForce.lean|, with \verb|#guard| examples taken
from the C program, and its theorems are in \verb|Ratpoints/Proof/BruteForce.lean|, each with a
guard on its axioms (\verb|#print axioms| under \verb|#guard_msgs|); the program is
\verb|Ratpoints/Model/Cli.lean| with \verb|Main.lean|, and the numbers and the search intervals of
its command line are read in \verb|Ratpoints/Model/CliNumbers.lean| (Chapter~\ref{chap:region}); the
statements for comparator are in \verb|comparator/|, and the differential tests in
\verb|scripts/difftest.py|.

\section{The evidence}\label{sec:spec-evidence}

Four independent checks against ratpoints~3.1.1 (tag \verb|v3.1.1|, the pin), run while this
chapter was written:
\begin{itemize}
  \item a literal Python implementation of the specification above compared with the program on
    7964 runs: 133 edge cases and 1200 random polynomials of degree 1 to 8 with heights up to 30,
    each with no option, \verb|-s|, \verb|-k| and \verb|-s -k|; 300 polynomials with a repeated
    factor; 120 curves with large coefficients (up to $2^{128}$, including $-2^{63}$ as the
    leading coefficient); 45 curves that tell the divisor order from ascending order; 300 curves
    at heights 31 to 120. Of these, 6011 runs were accepted and printed 69631 points: no point
    missing, none extra, no duplicate, including 719 accepted runs of polynomials that are not
    squarefree (under \verb|-s| or \verb|-s -k|), which confirms that the output theorem needs no
    squarefreeness. The refusals agreed exactly with the rules of Section~\ref{sec:refusals} (this
    check found that the rule for $c_0 = c_1 = 0$ under \verb|-s| applies to even $d$ only);
    $D = N$ on every accepted run; a model of the program's output order (the points at infinity
    first, then the denominators in the order of the loop, ascending or divisor by divisor, the
    numerators ascending, $+y$ before $-y$, and the effect of a reversal) matched all 6011 runs;
    and the output, order included, did not change under 19 settings of the sieving parameters
    and thread counts (14250 runs);
  \item a second implementation, with an exact model of the output order and Magma deciding
    squarefreeness in $\QQ[x, z]$ independently: the refusal set of a default run is exactly
    ``$\Phi_c$ not squarefree'' on 2337 polynomials (1223 refused), and the order model agreed
    with the program on 696 random runs, including 111 reversed ones;
  \item a compiled Lean prototype of the brute-force reference (core only), which agreed with
    the program as sets on the 195 \verb|test4.sh| runs of Section~\ref{sec:bruteForce}, on the
    1206 curves of the \verb|rptest| suites at heights 10 and 100, and on all their curves at
    height 1000; a model of the C order (reversal, divisor order) reproduced every one of these
    lists exactly;
  \item a reading of \verb|main.c| against the shipped binary, which reproduces \verb|testbase3|
    and \verb|testbase4| exactly, for the command line of Section~\ref{sec:cli}.
\end{itemize}
