\chapter{Delivery and the program}\label{chap:output}

The library function \verb|find_points| of ratpoints returns no list of points: it hands each point
that it finds to a function of its caller, the callback, which may count it, print it or stop the
search. This chapter describes how the model does the same, with the callback, its weights and its
stop, the options of the output \verb|RATPOINTS_NO_CHECK| and \verb|RATPOINTS_NO_Y|, what a search
writes back and the report of the library under \verb|RATPOINTS_VERBOSE|; and the program
\verb|ratpoints-lean|, which reads the command line of ratpoints and prints what ratpoints prints,
but for its banner. The reference of the delivery, with which the statements compare a search,
belongs to the specification (Definition~\ref{def:deliver}); the theorems on what a search delivers
and what the program prints are in Chapter~\ref{chap:theorems}; the components of the sieve that
pass the delivery on are those of Chapter~\ref{chap:sieve}.

\section{The callback and the delivery}\label{sec:outputCallback}

The header of the library declares the callback of \verb|find_points| and \verb|find_points_work|
(\csource{ratpoints.h}{436}{437}, \csource{ratpoints.h}{441}{442}) as
\verb|int proc(long, long, const mpz_t, void*, int*)|; the manual names its parameters \verb|x|,
\verb|z|, \verb|y|, \verb|info| and \verb|quit|. The library adds the value that each call returns
to a count \verb|total|, which it returns, or one of the negative codes of an error
(\csource{ratpoints.h}{427}{430}); a call stops the search by setting \verb|*quit|, which the
library clears before the search and tests after the steps that may have made calls
(Section~\ref{sec:outputStops}), so that it is clear at every call. Every refusal of the input comes
before the first call; only \verb|RATPOINTS_NO_MEMORY| can come after calls, when an allocation
fails, and the model has no allocation that can fail. The callback of the model and the delivery
that a search threads through its components are those of Definition~\ref{def:deliver}; the delivery
stands for the pointer \verb|info|, for the counts \verb|total| of the functions of the search as
one running count, and for the flags of the stop of the points at infinity and of the sieve
(\csource{find_points.c}{4570}{4571}, \csource{find_points.c}{3129}{3129}).

\begin{definition}[The flags of the check and the calls of a search]\label{def:callback}
  \uses{def:deliver}
  \lean{Ratpoints.CheckFlags, Ratpoints.Delivery.callMapped, Ratpoints.appendPoint, Ratpoints.Delivery.print}
  \leanok
  The flags of the check, which decide what the exact check and the points at infinity deliver:
  the bits \verb|RATPOINTS_REVERSED| (\csource{ratpoints.h}{414}{414}), \verb|RATPOINTS_NO_CHECK|
  and \verb|RATPOINTS_NO_Y| of the word of flags, as three Booleans, clear by default. One call
  (Definition~\ref{def:deliver}) with a point $(a : y : b)$ of the polynomial searched, mapped back
  to the caller's curve when the flag of the reversal is set: with $(b : y : a)$ for $a \ge 0$ and
  $(-b : y : -a)$ for $a < 0$, and with $(a : y : b)$ otherwise, the three branches that the exact
  check of the C code writes at each of its calls. The callback of the model that appends each
  point $(x, y, z)$ to an array, with the weight~$1$, and never stops the search; with it the data
  of a search is the list of the points that it delivers, in their order. And a text printed
  through the print channel of a search: the data as the channel leaves it, the count and the flag
  as they are (Section~\ref{sec:outputReport}).
\end{definition}

Apart from the flags of the check, which stand for bits of \verb|args->flags|, these definitions
model no C code of their own; the appending callback is that of $\mathrm{findPoints}$, of which the
statements speak (Definition~\ref{def:findPoints}).

\begin{lemma}[The delivery of a list]\label{lem:deliverList}
  \uses{def:deliver, def:callback}
  \lean{Ratpoints.Delivery.deliver_append, Ratpoints.Delivery.deliver_of_quit, Ratpoints.Delivery.deliver_eq_of_prefix, Ratpoints.Delivery.ite_quit_eq_deliver_append, Ratpoints.Delivery.deliver_appendPoint, Ratpoints.Delivery.exists_prefix_deliver_eq}
  \leanok
  The delivery of $L_1 \mathbin{+\!\!+} L_2$ is the delivery of~$L_2$ after that of~$L_1$. A
  delivery whose flag is set stays as it is, whatever the list; so if the delivery of a
  prefix~$M$ of~$L$ sets the flag, the delivery of~$L$ is that of~$M$, and a test of the flag after
  the delivery of~$L_1$, followed by the delivery of~$L_2$ when the flag is clear, is the delivery
  of $L_1 \mathbin{+\!\!+} L_2$. With the appending callback, from a delivery whose flag is clear,
  the array grows by~$L$ and the count by the length of~$L$. For every list~$L$ there is a
  prefix~$M$ of~$L$ whose delivery is that of~$L$, such that the flag is clear before each point
  of~$M$, so that each of them gets its call, and the delivery of~$M$ sets the flag unless $M = L$.
\end{lemma}

\begin{proof}
  \leanok
  By induction on the list, from the fold, in Lean core only, so that the contracts of the sieve,
  which are proved without Mathlib, can state what they deliver.
\end{proof}

\section{The stops}\label{sec:outputStops}

In the C code on one thread only a call of the callback sets the flag (with threads a worker also
sets it when the search has been stopped, \csource{find_points.c}{3610}{3610}), and each function
tests it after each step that may have made calls, returning its count at once when it is set:
\verb|_ratpoints_sift0| after the check of a numerator (\csource{sift.c}{1250}{1251},
\csource{sift.c}{1287}{1288}, and \csource{sift.c}{1168}{1169} in the arm of
\verb|USE_LONG_IN_PHASE_2|); \verb|sift| after each call of \verb|_ratpoints_sift0|
(\csource{find_points.c}{3611}{3611}); \verb|run_block| after each denominator, in each shape of the
loop (\csource{find_points.c}{3928}{3928}, \csource{find_points.c}{3957}{3957},
\csource{find_points.c}{4044}{4044}, \csource{find_points.c}{4068}{4068}); the loop over the blocks
after each block (\csource{find_points.c}{5158}{5158}); and \verb|find_points_work_1| after the
points at infinity, before it sieves (\csource{find_points.c}{5100}{5103}). So the calls made are
those of the search that no call stops, up to and including the first call that sets the flag, and
the count is the sum of their weights. With threads the calling thread of the C code delivers the
points of the blocks in their order; that blocks sifted apart and delivered in this way make the
calls of the run on one thread is the thread lemma (Theorem~\ref{thm:threads}), and that the pool
of ratpoints meets its hypotheses is read off the C code, not proved.

The model tests the flag at the same places, with one difference of form: where the C code returns
from \verb|_ratpoints_sift0| from within the walk through the set bits of a word, the walk of the
model returns, and its callers test the flag after each walk, and the scan of a piece after each
bit array, and return in turn; this makes no call that the C code does not make and skips none.
Every component of the sieve from the walk up to the run over the blocks takes the callback, the
flags and a delivery and hands them on (Chapter~\ref{chap:sieve}); its contract has the
precondition that the flag is clear and concludes that the delivery after it is the delivery
(Definition~\ref{def:deliver}) of a list, the points of the component in their order. Each loop
that may return early keeps an invariant with a case for the return at a stop, closed by
Lemma~\ref{lem:deliverList} (the invariants \lname{Ratpoints.Sieve.WalkDeliveryInvariant} of the
walk and \lname{Ratpoints.Sieve.SieveRunLoopInvariant} of the run over the blocks). So the search
with any callback delivers the list of the search with the appending callback, up to and including
the first call that stops it: the protocol of the delivery (Theorem~\ref{thm:protocol}).

\section{The options of the output}\label{sec:outputFlags}

Two bits of the flags of the caller change which points the library delivers
(\csource{ratpoints.h}{403}{404}): under \verb|RATPOINTS_NO_Y| only the point with $y \ge 0$ of a
pair $(x : \pm y : z)$ goes to the callback, and under \verb|RATPOINTS_NO_CHECK| every numerator
that passes the sieve goes to it with $y = 0$, without the exact check, whether or not it gives a
point. The C code reads them only in the exact check (\csource{find_points.c}{5250}{5338}), at the
points at infinity (\csource{find_points.c}{5068}{5099}), and \verb|RATPOINTS_NO_CHECK| also in a
line of the report; the reversal, the Sturm step, the exits, the tests on the denominators and the
sieve run as without them. Conversely, what \verb|RATPOINTS_NO_CHECK| delivers depends on everything
that decides which numerators pass the sieve: the moduli, the Jacobi test, the reversal and the
region of the Sturm step.

In the model the two options are the fields $\mathrm{noCheck}$ and~$\mathrm{noY}$ of the options of
a search, false by default (Definition~\ref{def:Options}), which the search copies, with the flag of
the reversal, into the flags of the check (Definition~\ref{def:callback}). What the points at
infinity deliver with these flags is the list of Definition~\ref{def:pointsAtInfinity}; what the
exact check (Chapter~\ref{chap:sieve}) delivers for one numerator to a callback that does not stop
the search is the following list, a definition of the proofs that holds no C code.

\begin{definition}[The points of a numerator with the flags]\label{def:checkNumWith}
  \uses{def:callback, def:reversal}
  \lean{Ratpoints.Sieve.checkPointList, Ratpoints.Sieve.checkNumWith}
  \leanok
  The points that the exact check of the numerator~$a$ over the denominator~$b$ delivers, for the
  products~$w$ of the coefficients with the powers of~$b$, the factor~$e$ ($b$ for odd degree, $1$
  for even degree) and the flags: under $\mathrm{noCheck}$ the survivor $(a, 0, b)$; otherwise,
  when the value of Horner's rule in~$a$ on~$w$, times~$e$, is~$y^2$ with $y \ge 0$, the point
  $(a, y, b)$ and, for $y \ne 0$, the point $(a, -y, b)$, which is left out under~$\mathrm{noY}$,
  and none when that value is no square; each mapped to the caller's curve when the flag of the
  reversal is set, $(a, y, b)$ to $(b, y, a)$ for $a \ge 0$ and to $(-b, y, -a)$ for $a < 0$. The
  points of a numerator with the flags: these when $\gcd(a, b) = 1$, and none otherwise.
\end{definition}

\begin{lemma}[The check and the points at infinity with the flags]\label{lem:checkNumWith}
  \uses{def:checkNumWith, def:pointsAtInfinity, def:candidate, def:callback, def:deliver, def:bruteForce}
  \lean{Ratpoints.Sieve.checkPoint_eq_deliver, Ratpoints.Sieve.checkNumWith_of_noCheck_eq_false, Ratpoints.Sieve.checkNumWith_of_noCheck_eq_true, Ratpoints.Sieve.map_checkNumWith_sublist, Ratpoints.Sieve.map_pointsAtInfinityList}
  \leanok
  On a delivery whose flag is clear, the exact check of a numerator delivers its list of
  Definition~\ref{def:checkNumWith}, as the points at infinity deliver theirs
  (Definition~\ref{def:pointsAtInfinity}): the second call of a pair, left out after a first call
  that stops the search, is the part of the delivery that a set flag passes over. Without
  $\mathrm{noCheck}$, the points of a numerator with the flags are those of the check of the
  reference (\lname{Ratpoints.Sieve.checkNum}), which tests $\gcd(a, b) = 1$ and the square as the
  brute-force reference does, mapped after a reversal, without those with $y < 0$
  under~$\mathrm{noY}$; under $\mathrm{noCheck}$ they are the survivor $(a, 0, b)$, mapped after a
  reversal, when $\gcd(a, b) = 1$, and nothing otherwise. With the exact check on
  and~$\mathrm{noY}$ set, the points of a numerator with~$y$ replaced by~$0$ form a sublist of its
  points under $\mathrm{noCheck}$, with the same flag of the reversal and either setting
  of~$\mathrm{noY}$, and the points at infinity with~$y$ replaced by~$0$ are those under
  $\mathrm{noCheck}$.
\end{lemma}

\begin{proof}
  \uses{lem:deliverList}
  \leanok
  Each call is the delivery of a list of one point, and the test of the flag between the two calls
  of a pair is the delivery of their concatenation (Lemma~\ref{lem:deliverList}). The rest by the
  cases of the flags: over one numerator the reference finds $(a, y, b)$ and $(a, -y, b)$, or
  $(a, 0, b)$, or nothing, so that the point with $y \ge 0$, with~$y$ replaced by~$0$, is the
  survivor, and the map of the reversal keeps~$y$.
\end{proof}

The contracts of the sieve carry these lists upwards: the search delivers the points at infinity
with the flags followed by the points with the flags of the numerators that pass the test of the
sieve, a test that depends neither on the callback nor on the flags. So the output under
\verb|RATPOINTS_NO_CHECK| holds, as a sublist and so in the same order, the survivors $(x, 0, z)$
of the points $(x, y, z)$ that the same search delivers with the exact check on and
\verb|RATPOINTS_NO_Y| set, and each of its elements has $y = 0$ and a normalized pair $(x, z)$ of
height at most~$H$ in the search region (Theorem~\ref{thm:noCheck}).

\section{What a search gives back}\label{sec:outputBack}

Besides the count, \verb|find_points| writes back what the program reads after the search: three
bits of \verb|args->flags| (\csource{ratpoints.h}{414}{417}), \verb|RATPOINTS_REVERSED|, set by the
reversal check, and \verb|RATPOINTS_USE_SQUARES| and \verb|RATPOINTS_USE_SQUARES1|, set for odd
degree when the leading coefficient is~$\pm 1$ and, otherwise, when the set-up of its divisors
succeeds (\csource{find_points.c}{4910}{4943}), for message~7; the search intervals as the Sturm
step leaves them, for message~8; and the numbers of the moduli used in the stages
(\csource{ratpoints.h}{378}{378}), for message~4. The outcome of a search in the model holds exactly
these, with the data of the callback and the count (Definition~\ref{def:Options}). The search sets
the bits before its exits and before the points at infinity, and it returns after the Sturm step
only for even degree, where the two bits of the squares are clear; so the bits and the intervals are
written back on every path that does not refuse the input, whatever the callback does. The numbers
of the moduli are zeroed on entry and set after the sieve from the moduli of the last block sifted,
so that they depend on where the callback stops the search (Chapter~\ref{chap:theorems}). Nothing
else is written back: the reversed coefficients and the private fields that the choice of the moduli
writes are not, and the bits of the input come back as the caller set them
(\csource{find_points.c}{4606}{4606}).

\section{The report of the library}\label{sec:outputReport}

Under the bit \verb|RATPOINTS_VERBOSE| of the flags (\csource{ratpoints.h}{407}{407}), which the
option \verb|-v| of the program sets, the library prints a report of the search on the standard
output, between the points that the callback of the program prints there. The model has no standard
output: the search takes a \emph{print channel}, a function that prints a text into the data of the
callback, which holds the standard output of the caller (Definition~\ref{def:callback}). The search
with a print channel is $\mathrm{findPointsVerbose}$, and $\mathrm{findPointsWith}$ takes by default
the channel that prints nothing (Definition~\ref{def:findPoints}).

\begin{definition}[The report of the library]\label{def:libraryReport}
  \uses{def:Options, def:choiceOfModuli, def:packing, def:setupUs1, def:reversal, def:sieveEntry}
  \lean{Ratpoints.Report.arguments, Ratpoints.Report.reversal, Ratpoints.Report.sturmStep, Ratpoints.Report.setup, Ratpoints.Report.packing, Ratpoints.Report.choice, Ratpoints.Report.moduli, Ratpoints.Report.excluded, Ratpoints.Report.sieving}
  \leanok
  The texts of the report, each as \verb|printf| prints it from the data that the C code prints,
  with \verb|%ld|, \verb|%3ld|, and \verb|%.pf| for the doubles and the values of \verb|Float| as
  glibc prints them, the exact value rounded to~$p$ places with ties to even: the arguments of the
  search as it normalizes them (\csource{find_points.c}{4691}{4725}); the outcome of the reversal
  check (\csource{find_points.c}{4740}{4743}, \csource{find_points.c}{4757}{4758},
  \csource{find_points.c}{4771}{4774}, \csource{find_points.c}{4791}{4801},
  \csource{find_points.c}{4804}{4807}); the Sturm step (\csource{find_points.c}{4864}{4878}); the
  points at infinity and the tests on the denominators (\csource{find_points.c}{4897}{4898},
  \csource{find_points.c}{4915}{4918}, \csource{find_points.c}{4921}{4926},
  \csource{find_points.c}{4928}{4941}, \csource{find_points.c}{4946}{4947}); the packing of the
  classes of the numerators (\csource{find_points.c}{4969}{4985}); the choice of the moduli
  (\csource{find_points.c}{3089}{3095}), the moduli of the three stages with the cost of an exact
  check (\csource{find_points.c}{5027}{5042}) and the forbidden divisors
  (\csource{find_points.c}{5043}{5048}); and the lines before the sieve
  (\csource{find_points.c}{5111}{5113}).
\end{definition}

Four texts complete the report: the two exits on the way (\lname{Ratpoints.Report.noClasses},
\lname{Ratpoints.Report.noPoints}), the line before the points at infinity
(\lname{Ratpoints.Report.atInfinity}) and the forbidden valuations
(\lname{Ratpoints.Report.excludedValuations}). Each text is printed where the C code prints it, or
once from the result of a check where the C code prints in its course. The report is compared byte
for byte with that of the C program (Chapter~\ref{chap:ccode}) and not proved: with the print
channel that prints nothing every text vanishes (\lname{Ratpoints.findPointsWith\_eq}), and the
theorems speak about that channel.

\section{The program}\label{sec:outputProgram}

The executable \verb|ratpoints-lean| has the command line of ratpoints: the coefficients
$c_0, \dots, c_n$ of $y^2 = c_n x^n + \dots + c_0$ as one argument, the height bound and the
options. It reads them as \verb|main.c| does, with its checks, messages and exit statuses in its
order, runs the search with the callback of \verb|main.c|, and prints what ratpoints prints, but for
the banner and the usage, which name \verb|ratpoints-lean|, so that the test scripts of the C
repository can run it in place of ratpoints. Its root \verb|Main.lean| imports only the model, so
that the program depends neither on Mathlib nor on the proofs. It acts on every option of ratpoints
but \verb|-t|, the number of threads, which it checks and ignores: the model sifts the blocks of
the run in turn, and the thread lemma (Theorem~\ref{thm:threads}) shows that blocks sifted apart
under hypotheses that the pool of ratpoints meets by its code, and delivered in their order, give
the same output.

\begin{definition}[The command line]\label{def:cliInput}
  \uses{def:cliNumbers, def:Options, def:maxDegree}
  \lean{Ratpoints.Cli.input, Ratpoints.Cli.checkOptions, Ratpoints.Cli.Output, Ratpoints.Cli.Failure, Ratpoints.Cli.Failure.message}
  \leanok
  The coefficient list, the height bound, the options of the sieve, the options of the search and
  the settings of the output that a command line gives, or its first failure, in the order of
  \verb|main.c|. Fewer than two arguments fail with error~2 (\csource{main.c}{210}{214}). The first
  argument gives the coefficients, constant term first, integers separated by white space: a word
  that is not an integer fails with error~11 wherever it stands, then more than
  $\mathrm{maxDegree} + 1$ integers fail with error~3 and fewer than two with error~5. The second
  gives the height bound, a C \verb|long| of at least~$1$, or error~4. The options are read from
  left to right, the last setting of each kind winning. An unknown option, an argument among the
  options that does not begin with \verb|-|, a missing or malformed argument of an option (but for
  \verb|-l| and \verb|-u|) and \verb|-f| or \verb|-d| followed by another character fail with
  error~6 (\csource{main.c}{393}{400}, \csource{main.c}{437}{532}, \csource{main.c}{533}{577},
  \csource{main.c}{638}{649}, \csource{main.c}{650}{668}); \verb|-l| and \verb|-u| read the ends of
  the search intervals (Definition~\ref{def:cliNumbers}), with error~7 for ends that are missing, no
  numbers, not alternating, too many or not ordered. Then a pending interval is completed, the
  format is \verb|(%x : %z)\n| under \verb|-x| or \verb|-y| and \verb|(%x : %y : %z)\n| otherwise,
  unless \verb|-f| gave one, and \verb|-q| cancels \verb|-v| (\csource{main.c}{688}{688}). A failure
  prints the message of the function \verb|error| of \verb|main.c|, for errors~2 and~6 with the
  banner and the usage (\csource{main.c}{1036}{1048}).
\end{definition}

\begin{definition}[The numbers and the search region of the command line]\label{def:cliNumbers}
  \uses{def:Double}
  \lean{Ratpoints.Cli.longOfString?, Ratpoints.Cli.strtod, Ratpoints.Cli.scanDouble?, Ratpoints.Cli.scanEnd, Ratpoints.Cli.Intervals, Ratpoints.Cli.inRegion, Ratpoints.Cli.joinIntervals}
  \leanok
  The readers of the numbers, on the words of an argument, its maximal runs of characters other
  than C white space: an integer of the coefficient list as \verb|scan_mpz| reads it, with an
  optional sign and of any size; a C \verb|long| as \verb|scan_long| reads it, from~$-2^{63}$
  to~$2^{63} - 1$, with only white space around it (\csource{main.c}{733}{740}); and a real number
  as \verb|scan_double| reads it, the double that \verb|strtod| of glibc reads in the C locale, none
  for a NaN (\csource{main.c}{746}{752}): $\pm\infty$ for an infinity, and otherwise the double
  nearest to the exact value $\pm m\,10^{e - k}$ of the word, or $\pm m\,2^{e - 4k}$ for a
  hexadecimal word, with ties to even. An end of a search interval as \verb|scan_end| reads it: the
  number that the argument denotes, or an infinity, also for a number beyond the range of the
  doubles, and $\pm 2^{-1075}$ for a nonzero number that \verb|strtod| reads as~$0$, which lies
  between~$0$ and every other~$x$ of the search as the number does; with the double that the
  library is given for it, the double of \verb|strtod| moved outward to the largest double at most
  a lower end, or the smallest double at least an upper end (\csource{main.c}{798}{806}). The
  reading of the intervals of \verb|-l| and \verb|-u| into the doubles and the exact ends of at most
  $\mathrm{maxDegree}$ intervals (\csource{main.c}{66}{66}, \csource{main.c}{73}{73}), a missing
  first lower end or last upper end standing for~$\mp\infty$ with the double~$\mp h$ of the height
  bound, or~$\mp\infty$ when that double would turn the interval round. The test whether~$a/b$ lies
  in one of these intervals, by the binary search of \verb|in_region| over their exact ends
  (\csource{main.c}{126}{137}). And the intervals that the library is given, those of the command
  line joined where their doubles meet or overlap (\csource{main.c}{891}{905}).
\end{definition}

\begin{lemma}[The numbers of the command line]\label{lem:cliNumbers}
  \uses{def:cliNumbers, def:regionSpec, def:Double}
  \lean{Ratpoints.Cli.isNaN_strtod, Ratpoints.Cli.lt_nextUp_strtod, Ratpoints.Cli.outward_spec, Ratpoints.Cli.run_scanEnd_isMaxBelow, Ratpoints.Cli.inRegion_spec, Ratpoints.Cli.joinIntervals_spec}
  \leanok
  \verb|strtod| never gives a NaN, and when it gives a finite double other than zero for a word that
  is not an infinity, the exact value of the word lies below the next double above it: half of a
  faithful rounding, the half that the lower ends need. \verb|outward| moves a double to the side
  of the end that its direction asks, and onto the largest double at most a lower end when it starts
  from a double whose next double lies above the end; so for an argument of fewer than~$2^{56}$
  characters the double that \verb|scan_end| gives for a lower end is the largest double at most the
  end (for an upper end the proofs show only that it is at least the end). The binary search of
  \verb|in_region| decides whether~$a/b$ lies in increasing and disjoint exact intervals. For
  intervals without a NaN, \verb|join_intervals| gives no interval exactly when it is given none,
  and intervals without a NaN that hold every number that the given ones hold; when moreover each
  lower end is at most its upper end and the lower ends increase from the second on, its intervals
  are increasing and strictly apart, search intervals in the sense of the specification
  (Definition~\ref{def:regionSpec}).
\end{lemma}

\begin{proof}
  \uses{lem:doubleValues}
  \leanok
  The parts of a word give its exact value, and the exponent that \verb|scan_end| accumulates, which
  stops at \verb|LONG_MAX / 20|, is the exact one for arguments of fewer than~$2^{56}$ characters
  whose double is finite and not zero; the rounding of \verb|strtod| is that of the doubles
  (Chapter~\ref{chap:region}). The loops of \verb|outward|, \verb|in_region| and
  \verb|join_intervals| are proved by named invariants with the program logic of Lean core.
\end{proof}

\begin{definition}[The callback of the program]\label{def:cliProcess}
  \uses{def:deliver, def:cliNumbers}
  \lean{Ratpoints.Cli.Data, Ratpoints.Cli.process, Ratpoints.Cli.formatPoint, Ratpoints.Cli.escape, Ratpoints.Cli.printString, Ratpoints.Cli.Data.keeps}
  \leanok
  The data that \verb|main.c| passes to its callback \verb|process| (\csource{main.c}{110}{113}):
  whether a point was printed, the settings of the output that \verb|process| reads, the search
  intervals of the command line, before they are joined, with their exact ends, and the text printed
  so far. The callback on $(x, z, y)$ (\csource{main.c}{139}{142}, \csource{main.c}{150}{156})
  passes over, with the weight~$0$ and the flag clear, a point at infinity under \verb|-i| and an
  affine point whose~$x/z$ lies in none of the search intervals of the command line, when it gives
  some (the library searches them with the doubles outward of the exact ends); every other point is
  one that it keeps. It gives such a point the weight~$1$, stops the search at it under \verb|-1|,
  and prints it in the format unless \verb|-z|, after the string before the points if it is the
  first point printed and after the string between them otherwise. The format prints \verb|%x|,
  \verb|%y| and \verb|%z| as the coordinates in decimal (\verb|%y| as itself under \verb|-x| or
  \verb|-y|), \verb|\t|, \verb|\n|, \verb|\\| and \verb|\%| as a tab, a line feed, a backslash and a
  percent sign, and every other character as itself (\csource{main.c}{157}{177},
  \csource{main.c}{178}{182}, \csource{main.c}{183}{186}); a string prints in the same way, its
  percent signs not special (\csource{main.c}{952}{960}).
\end{definition}

The delivery of a list to this callback prints, unless \verb|-z|, the points of the list that it
keeps, under \verb|-1| only the first of them, and its count is their number
(\lname{Ratpoints.Cli.deliver\_process}); the theorem on what the program prints
(Theorem~\ref{thm:cliRun}) rests on this and on the protocol of the delivery.

\begin{definition}[The program and its report]\label{def:cliRun}
  \uses{def:cliInput, def:cliProcess, def:cliNumbers, def:findPoints, def:Options, def:libraryReport}
  \lean{Ratpoints.Cli.run, Ratpoints.Cli.main, Ratpoints.Cli.preamble, Ratpoints.Cli.report, Ratpoints.Cli.Message.text}
  \leanok
  The messages of the report of \verb|main.c| (\csource{main.c}{979}{1033}), among them the search
  region of the command line (message~3), the numbers of the moduli used (message~4), what the
  search did, from the bits written back (message~7), the search intervals as the search leaves
  them (message~8), and the count of the points, or of the point pairs under \verb|-x| or \verb|-y|
  (message~2). The program on a command line (\csource{main.c}{195}{198}): on a failure of the
  command line, the message and the status of the failure. Otherwise, unless \verb|-q|, the head of
  the report: the banner, the curve, the height bound unless \verb|-v|
  (\csource{main.c}{215}{220}), and message~3 when the command line gives intervals
  (\csource{main.c}{224}{224}); then the search with a print channel
  (Definition~\ref{def:findPoints}), with the options of the sieve of the command line and the array
  size that \verb|main.c| sets (\csource{main.c}{221}{222}), the options of the search on the joined
  intervals (\csource{main.c}{248}{248}), the callback of the program on its data and, under
  \verb|-v|, the print channel that appends to the text of the data (\csource{main.c}{251}{252}). On
  a refusal it prints what the library printed and the message of the error that \verb|main.c| gives
  for it (\lname{Ratpoints.Cli.Failure.ofRefusal}: error~8 for a binary form that is not
  squarefree), and exits with that status. Otherwise it prints what the callback and the library
  printed, the string before the points if no point was printed (\csource{main.c}{265}{265}), the
  string after them (\csource{main.c}{267}{267}) and, unless \verb|-q|, the end of the report: two
  line feeds and messages~4, 7 and~8 unless \verb|-v|, then message~2 (\csource{main.c}{268}{276});
  its status is~$0$ (\csource{main.c}{284}{285}).
\end{definition}

The exit statuses are thus those of \verb|main.c|: $0$ after a search, $2$ to~$7$ and~$11$ for the
command line, $8$ for a binary form that is not squarefree, and~$9$ for search intervals that the
library refuses (\verb|main.c| gives~$9$ for every code of the library but those of errors~8
and~10); by Theorem~\ref{thm:cliRun} no command line whose arguments are shorter than~$2^{56}$
characters leads to error~$9$. Error~$10$, for lack of memory, has no counterpart. When the reader
of its output is gone, \verb|SIGPIPE| ends ratpoints and the shell reports the status
$141 = 128 + 13$; the Lean runtime ignores that signal, and \verb|ratpoints-lean| exits quietly with
the status~$141$ when its write fails.

\begin{remark}[Deviations]\label{rem:outputDeviations}
  Besides the deviations stated above, the program keeps the data of \verb|main.c| as a value with
  the text printed so far, for the pointer \verb|info| and the standard output, and writes its
  output once, at the end, where \verb|main.c| prints and flushes after each point. It reads the
  formats and the strings as Lean strings, decoded from the command line as UTF-8, where
  \verb|main.c| copies the bytes; since every escape of \verb|main.c| is ASCII and no byte of a
  multibyte character of UTF-8 is, both print the same bytes for every format and string in UTF-8.
  The lines of \verb|main.c| without a counterpart, such as the includes and the initialization of
  the GMP integers, are excluded in the record (Chapter~\ref{chap:ccode}).
\end{remark}
